## 3. Canonical Four-Table Schema
The active application datastore consists of **strictly four physical Google Sheets tables**. No other operational tables exist.

### 3.1 Table 1: `Students` (10 columns)
`student_id, student_name, parent_name, parent_phone, parent_email, student_phone, student_email, subject, status, primary_meeting_link`
- `student_id`: Unique immutable identifier (`STU_001` to `STU_026` format). Primary key.
- `status`: Enum (`ACTIVE`, `INACTIVE`, `ARCHIVED`).
- `primary_meeting_link`: Embedded primary virtual classroom link. Managed directly in Students directory.

### 3.2 Table 2: `Packages` (12 columns)
`student_id, student_name, plan_type, currency, package_price, per_class, classes_purchased, start_date, end_date, next_due_date, class_duration, class_schedule`
- **No `package_id` column** exists in the physical sheet; packages link directly to `Students.student_id`.
- `class_duration`: Duration in minutes (default 60).
- `class_schedule`: Serialized weekly recurring schedule pattern (e.g. `Mon - 6:00 PM, Wed - 6:00 PM`).

### 3.3 Table 3: `Payments` (6 columns)
`student_id, student_name, payment_date, amount, currency, in_inr`
- **No payment status column** exists in the physical sheet.
- Voided payments are physically removed via `sheet.deleteRow()` with a durable tombstone recorded in `ScriptProperties` (`payment_void_<id>`).
- Foreign payments retain original currency; unconverted foreign amounts contribute 0 to INR totals.

### 3.4 Table 4: `ClassSessions` (9 columns)
`student_id, student_name, schedule_date, schedule_time, attendance_status, session_status, deduct_class, cancellation_reason, session_notes`
- **No `session_id` column** and **no stored end-time column** exist in the physical sheet.
- Sessions are addressed by composite key `student_id__schedule_date__schedule_time` (or 1-based row index `_rowIndex`).
- End time is dynamically derived as `schedule_time + Packages.class_duration`.
- `session_notes` stores pedagogical lesson coverage and remarks independently from `cancellation_reason`.

### 3.5 Retired & Archived Sheets
- Permanently retired from application management: `MeetingLinks`, `StudentNotes`, `Enrollments`, `FeeObligations`, `ClassSchedules`, `AppConfig`, `ImportBatches`, `ImportRowResults`.
- Archived for reference in spreadsheet: `_Archived_Historical_Notes`, `_Archived_ClassSchedules`, `_Backup_PreFourTable_*`, `StudentId_Migration_Backup`.

## 4. Non-Negotiable Technical and Business Invariants
1. **Four Physical Tables Only:** Never introduce additional operational tables or add surrogate ID columns (`package_id`, `payment_id`, `session_id`) to the physical sheets.
2. **Micro-File Limit:** Every source file under `src/` and `public/` must remain strictly $\le 149$ lines. Catch-all files (`utils.ts`, `helpers.ts`, `app.js`, etc.) are prohibited. Checked via `npm run check:lines`.
3. **Package Renewal & Balance Derivation:**
   - On renewal, a new package row is appended storing only the newly purchased classes (`classes_purchased = newClasses`).
   - The historical package row remains intact and is never overwritten or deleted.
   - Aggregate student available balance is dynamically derived:
     $$\text{Remaining Balance} = \sum(\text{classes\_purchased across all packages}) - \sum(\text{ClassSessions where deduct\_class = true})$$
   - Carried-forward classes do not increase the new package price. Remaining classes are not monetary credit.
4. **Financial Accounting Rules:**
   - Grouped strictly by currency; foreign currency amounts (USD, GBP, EUR) are never added directly to INR without manual `in_inr`.
   - Outstanding amount is:
     $$\text{Outstanding} = \max(0, \text{Total Package Payable} - \text{Total Recorded Payments})$$
   - Excess payment is displayed separately as available credit ($\max(0, \text{Paid} - \text{Payable})$); outstanding balance never becomes negative.
   - Missing or invalid numeric values must be treated as unreliable/unavailable (`isReliable: false`), not silently coerced to zero.
   - No FIFO obligation allocation, no physical payment status column, and no automatic third-party exchange rate conversion.
5. **Class Attendance & Cancellation Deduction:**
   - Attended sessions (`PRESENT`/`ATTENDED`): `deduct_class = true`.
   - Advance cancellation ($\ge 4$h notice) or explicit credit waiver: `deduct_class = false`, `attendance_status = 'CANCELLED'`. Automatically schedules a replacement session at the next available recurring slot and extends package `end_date`.
   - Late cancellation ($< 4$h notice without waiver): `deduct_class = true`, `attendance_status = 'CANCELLED_LATE'`.
   - User must supply explicit cancellation reason, stored in `ClassSessions.cancellation_reason`. `session_notes` is preserved independently.
6. **Schedule Persistence & Concurrency:**
   - `Packages.class_schedule` is the canonical storage for recurring weekly schedule patterns.
   - All writers to `Packages.class_schedule` (including `Schedules_save` and `RenewalService`) must hold the shared script lock (`LockManager.withLock`) to prevent race conditions.
   - `LockManager.withLock` supports execution-local reentrancy, allowing nested calls within the same execution context without self-deadlock.

## 9. Known Limitations and Recovery Rules
1. **Absence of Session ID in ClassSessions:**
   - Sessions are identified by composite key `student_id__schedule_date__schedule_time` or row index `_rowIndex`.
   - **Operational Rule:** Never manually sort, insert, or delete rows directly in Google Sheets while application operations are in progress. Manual shifts invalidate client-held `_rowIndex` values.
2. **Fail-Closed Renewal Interruption Recovery:**
   - If execution fails between package insertion and completion persistence, or if ScriptProperties state is lost, the renewal recovery flow fails closed with `AMBIGUOUS_RENEWAL_RECOVERY` to prevent duplicate package or payment insertion.
   - In ambiguous states, administrator must inspect the Packages sheet and reconcile manually.
3. **No External Currency Conversion API:**
   - The application does not call third-party exchange rate APIs. If a foreign currency transaction lacks manual `in_inr`, it contributes 0 to INR totals.

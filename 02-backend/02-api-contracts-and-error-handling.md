## 2. API Architecture & Request Transport

1. **HTTP Transport:** All operations are dispatched via HTTP POST to the deployed Apps Script Web App URL with `Content-Type: text/plain;charset=utf-8` to eliminate CORS preflight.
2. **Server-Side Authentication:** Protected operations must provide an HMAC-SHA256 session token signed with `ADMIN_AUTH_KEY` and matching `ashreya0502@gmail.com`.
3. **Transient Identifiers:** Physical Google Sheets tables have no `package_id`, `payment_id`, or `session_id` columns. Transient identifiers generated by API handlers or clients are mapped back to student IDs, row indices, or composite keys on the server.

### 2.1 Standard Request Envelope
```json
{
  "apiVersion": "1",
  "operation": "packages.renew",
  "identityToken": "eyJhbGciOiJIUzI1NiJ9...signature",
  "requestId": "req_1730000000000_abc123",
  "idempotencyKey": "idemp_optional_uuid",
  "payload": { ... }
}
```

### 2.2 Standard Success Response Envelope
```json
{
  "apiVersion": "1",
  "requestId": "req_1730000000000_abc123",
  "ok": true,
  "data": { ... },
  "error": null,
  "meta": {
    "totalCount": 26,
    "timestamp": "2026-11-17T12:00:00.000Z"
  }
}
```

### 2.3 Standard Error Envelope & Error Codes
```json
{
  "apiVersion": "1",
  "requestId": "req_1730000000000_abc123",
  "ok": false,
  "data": null,
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Student ID is required",
    "details": { "student_id": "Required" },
    "retryable": false
  }
}
```

Standard Error Codes:
- `UNAUTHORIZED`: Missing, forged, or expired session token.
- `ACCESS_DENIED`: Valid token, but identity is not allowlisted administrator.
- `VALIDATION_ERROR`: Missing required fields, invalid numbers, or incorrect formats.
- `RECORD_NOT_FOUND`: Target student, package, payment, or session does not exist.
- `AMBIGUOUS_RECORD`: Multiple identical records exist without unique discrimination.
- `AMBIGUOUS_RENEWAL_RECOVERY`: Renewal retry interrupted and prior state cannot be verified unambiguously.
- `LOCK_TIMEOUT`: Shared ScriptLock could not be acquired within timeout.
- `SCHEDULING_CONFLICT`: Session overlaps with an existing scheduled session for the same student.
- `INTERNAL_ERROR`: Unhandled runtime exception wrapped by `ResponseFactory.gs`.

## 3. Package & Renewal Contracts

### 3.1 `packages.renew` / `students.renew`
Executes package renewal workflow under shared ScriptLock (`RenewalService.Packages_renew`).

#### Request Payload
```json
{
  "student_id": "STU_001",
  "classes_purchased": 12,
  "package_price": 6000,
  "currency": "INR",
  "plan_type": "PACKAGE",
  "class_duration": 60,
  "start_date": "2026-11-20",
  "class_schedule": "Mon - 6:00 PM, Wed - 6:00 PM",
  "schedules": [
    { "day_of_week": "Monday", "start_time": "18:00", "end_time": "19:00" }
  ],
  "first_class_date": "2026-11-20",
  "payment": {
    "amount": 6000,
    "payment_date": "2026-11-20",
    "currency": "INR",
    "in_inr": 6000
  },
  "idempotency_key": "idemp_ren_173000..."
}
```

#### Behavior & Invariants
1. Acquires shared ScriptLock (`LockManager.withLock`).
2. Checks durable checkpoints in `ScriptProperties` using `idempotency_key`.
3. If previously completed, returns idempotent success with cached data.
4. If interrupted after package append, verifies persisted row against complete physical package snapshot. Fails closed with `AMBIGUOUS_RENEWAL_RECOVERY` if ambiguous.
5. Appends a new package row to `Packages` storing `classes_purchased = 12`. Historical package row is never overwritten.
6. If optional `payment` is provided, appends payment to `Payments` (6 columns).
7. Schedules future sessions according to recurring schedule.
8. Writes completion checkpoint to `ScriptProperties`.

## 4. Schedule Persistence Contracts

### 4.1 `schedules.save`
Persists recurring weekly schedule to `Packages.class_schedule`.

#### Request Payload
```json
{
  "student_id": "STU_001",
  "schedules": [
    { "day_of_week": "Monday", "start_time": "18:00", "end_time": "19:00" },
    { "day_of_week": "Wednesday", "start_time": "18:00", "end_time": "19:00" }
  ]
}
```

#### Behavior & Locking
1. Acquires shared ScriptLock via `LockManager.withLock`. Supports execution-local reentrancy.
2. Locates student's latest package in `Packages`.
3. Serializes schedule entries into canonical string (`Mon - 6:00 PM, Wed - 6:00 PM`).
4. Writes serialized string to column 12 (`class_schedule`).
5. Returns updated schedule entries.

## 5. Payments Contracts

### 5.1 `payments.record`
Appends a payment record to the `Payments` sheet (6 columns).

#### Request Payload
```json
{
  "student_id": "STU_001",
  "payment_date": "2026-11-20",
  "amount": 6000,
  "currency": "INR",
  "in_inr": 6000,
  "idempotency_key": "idemp_pay_173000..."
}
```

#### Behavior
- Validates amount $> 0$ and valid date.
- Idempotency key checked in memory and `ScriptProperties`. Duplicate requests return the original record.
- Appends row: `student_id, student_name, payment_date, amount, currency, in_inr`.

### 5.2 `payments.void`
Physically deletes the matching payment row from the `Payments` sheet.

#### Request Payload
```json
{
  "payment_id": "pay_STU_001_2026-11-20_6000",
  "student_id": "STU_001",
  "amount": 6000,
  "payment_date": "2026-11-20",
  "void_reason": "Administrative correction / duplicate entry"
}
```

#### Behavior
- In the 6-column physical schema, there is no payment status column.
- Locates matching row by student, amount, and date.
- If multiple identical matching rows exist without unique discrimination, rejects with `AMBIGUOUS_RECORD`.
- Physically removes matching row via `sheet.deleteRow()`.
- Records durable tombstone `payment_void_<id>` in `ScriptProperties`.
- Subsequent void retries return idempotent success.

## 6. Class Sessions Contracts

### 6.1 `classes.complete`
Marks a scheduled session completed with attendance outcome and balance deduction.

#### Request Payload
```json
{
  "class_session_id": "STU_001__2026-11-20__18:00",
  "_rowIndex": 15,
  "student_id": "STU_001",
  "attendance_status": "PRESENT",
  "deduct_class": true,
  "session_notes": "Covered quadratic equations and factoring."
}
```

#### Behavior
- Matched by `_rowIndex` (with student ID verification) or composite key `student_id__schedule_date__schedule_time`.
- Sets `session_status = 'COMPLETED'`, `attendance_status = 'PRESENT'`, `deduct_class = true`.
- If provided, updates `session_notes` in column 9.

### 6.2 `classes.cancel`
Cancels a scheduled class session.

#### Request Payload
```json
{
  "class_session_id": "STU_001__2026-11-20__18:00",
  "_rowIndex": 15,
  "student_id": "STU_001",
  "cancellation_reason": "Student unwell, notified 24h in advance",
  "credit_waiver": true,
  "session_notes": "Lesson rescheduled for next Tuesday."
}
```

#### Behavior
- `cancellation_reason`: Required non-blank text. Saved to `ClassSessions.cancellation_reason` (column 8).
- `session_notes`: Preserved independently in column 9; not overwritten by cancellation reason.
- If cancelled $\ge 4$h in advance or waived: `deduct_class = false`, `attendance_status = 'CANCELLED'`, and automatically inserts a replacement session at the next available recurring slot, extending package `end_date`.
- If cancelled $< 4$h in advance without waiver: `deduct_class = true`, `attendance_status = 'CANCELLED_LATE'`.

### 6.3 `classes.restoreCredit`
Restores class credit on an erroneously deducted session.

#### Request Payload
```json
{
  "class_session_id": "STU_001__2026-11-20__18:00",
  "_rowIndex": 15,
  "student_id": "STU_001"
}
```

#### Behavior
- Locates session, verifies `deduct_class === true`, and updates the existing row in place setting `deduct_class = false`.
